# LingoFlow 本机翻译模型对照 · 2026-09-26

**本轮建议优先把 MiLMMT-46-4B-v1.0 作为下一阶段的默认模型候选；Hy-MT2 1.8B 可作为速度优先选项。**
MiLMMT 在这组题目的英译中、日译中可读条数和药物发现子集均有较好表现，耗时和驻留量也低于当前 7B 配置。

**测试范围。** 相同 50 条预先固定的合成文本：25 条英语、25 条日语，均译为简体中文；包含 8 条 AI 药物发现文本（英语 5、日语 3）。
四个模型均完成 50/50 条正式请求，全部正常结束，无传输失败、空输出或输出预算截断。
完整输出并不等于翻译正确：旧模型有一条输出了大段阿拉伯语，该条仍计入分母并评为 0 分。
下载后的接口预检另有每模型 2 条，不进入正式评分。未使用私人论文或在线推理服务。

译文按每个案例分别随机打乱、隐藏模型名，由本次助手对照原文和预设检查点逐条评分，记录全部 200 条理由后才解码汇总。
这是助手主观审阅，不是独立专业人工双盲 MQM，也没有把参考译文的字面相似度当成正确率。

**对 AI 药物发现阅读最有意义的差别。**

通用文本也有共性弱点：E09 的两个 bank，四个模型都把第二个“银行”误作河岸。
日语使役被动 J06 中，旧模型和 Hy-MT2 颠倒了部长与重写报告者的关系。
本轮不能只按中文是否顺口来判断译文可用性。

**接入 LingoFlow 的判断。**

1. 优先适配 MiLMMT：使用官方纯文本补全格式和显式源语言，接到现有流式、取消及分段流程。
   当前客户端统一使用 `/api/chat` 与通用系统提示，直接换标签不能复现本次结果。
2. Hy-MT2 保留为快速候选。HF 到 Ollama 的自动模板转换在本机产生缺少用户文本、含 `onse }}` 的损坏模板；
   本轮已通过官方模板的 raw 请求绕开，因此质量分数不是损坏模板导致的。已下载的原始标签没有被改写，
   应用接入仍需同样的模板适配。其 Q8 模型本次已经很小，无需为了缩减体积立刻进一步量化。
3. 加入可维护的 AI 药物发现术语表，优先覆盖 scaffold splitting、sanitization、conditioned on、pose、sampling。
   要根据模型官方接口判断术语如何传入；这些额外提示不属于本轮结果，不能先声称会提高质量。
4. 默认切换前，用日常论文的真实选区检查 MiLMMT 的方法段、结果限制和长段落，保留旧模型作为对照。
   TranslateGemma 可用于术语复核候选，本轮不优先将其设为主模型。以上是下一阶段建议，本次未实施应用行为变更。

**复现与证据。** 本轮比较的是实际可用配置，不是只改变模型权重的控制实验：量化精度不同，各模型使用官方相应提示与采样策略；
当前基线沿用应用的 auto 源语言和现有系统提示。其社区 Chimera 标签的导入模板还含字面 `TEMPLATE """`，
本轮保留现状，不能由此推断原始官方 Hunyuan 模型本身的能力。没有进行温度、提示词或不同种子的择优复测。
