- 技术基线：Python 3.12、PyQt6、AppKit/Quartz、Ollama；只支持 macOS。
- 默认模型：`hf.co/mradermacher/MiLMMT-46-4B-v1.0-GGUF:Q4_K_M`。
- 当前用户快捷键为 `Option+D` 翻译、`Option+S` OCR。早期对话提过 Ctrl+D，不应据此覆盖实际配置。

本次范围是窗口交互、阅读界面、编辑入口、菜单与设置的信息组织。沿用已有翻译引擎和技术栈，允许为可靠的 macOS 窗口行为增加局部原生适配；不扩展 Windows 支持，不重新开展模型选型或整栈迁移。

## 2. 用户反馈与定位证据

| 用户反馈 | 已知实现与判断 |
| --- | --- |
| 菜单栏 About 点两次才出现 | `MainController._show_about()` 直接调用无父窗口的 `QMessageBox.about()`，没有采用 Settings 已有的前台激活流程。应用激活、菜单关闭与窗口前置的时序是主要排查方向，尚未通过真实点击复现确认唯一原因。 |
| 看似未固定，点外面不消失；关闭后再开仍像固定 | 排查时 `settings.json` 的 `hide_on_focus_loss=true`，`window-state.json` 的 `pinned=true`。`TranslationPopup.__init__()` 在连接信号前恢复按钮勾选，而初始文字仍为 `Pin`；因此真实状态和可见文字可以不一致。固定状态还会写入下一次窗口。 |
| Pin / Unpin 闪烁 | `PopupWindowController.set_pinned()` 修改 `WindowStaysOnTopHint` 后再次 `show()`。Qt 明确说明修改该窗口标志会隐藏窗口，当前实现存在与闪烁吻合的隐藏/重显路径。 |
| 未固定的窗口有时仍不收起 | `_auto_dismiss_allowed()` 在翻译中、原文编辑/校对中禁止自动关闭。用户看不到这些例外，不能仅从图钉判断窗口行为。 |
| 界面复杂 | 语言、Source、Pin、自定义关闭、两种朗读、Stop、Retry、Latest、Copy 分布在多行；阅读、编辑、校对与调试性质的状态混在同一界面。 |

上述配置值是当时的只读快照，不应当作永久状态。代码入口见文末导航。

框架依据：[Qt QWidget::setWindowFlag](https://doc.qt.io/qt-6/qwidget.html#setWindowFlag)。About 的具体故障链仍需执行时验证，不能把推断写成已复现结论。

## 3. 窗口行为约定

### 3.1 临时翻译浮窗

| 情境 | 目标行为 |
| --- | --- |
| 创建一个新的翻译浮窗 | 默认未固定。旧磁盘状态中的 `pinned=true` 不应使新窗口隐式常驻。 |
| 未固定时点击桌面或其他应用 | 收起窗口；如有请求进行中，同时取消当前会话。加载中、流式中、完成、停止和出错状态遵循同一规则。 |
| 固定后点击外部 | 窗口保持可见，位于普通应用窗口上方，但不反复抢占键盘焦点。 |
| 取消固定 | 图标与行为立即变为未固定；本次点击不导致窗口立即关闭，下一次外部点击才收起。 |
| 点击窗内、拖动、缩放、选择/复制文字 | 不收起，不丢失当前内容、选区或阅读位置。 |
| 操作本窗口的下拉框、右键菜单、复制或朗读菜单 | 这些属于窗口内部交互，不误判为外部点击。鼠标仅移到窗口外也不收起。 |
| 用户切换到另一应用 | 未固定浮窗按离开阅读处理；须区分真正切换应用与打开本应用菜单/子窗口造成的短暂失焦。 |
| 点击关闭或按 Escape | 关闭窗口、结束本窗口的固定状态、取消当前请求并停止本窗口的朗读。 |
| 同一个仍打开的窗口收到新翻译 | 保留本窗口的固定状态与用户调整后的几何，替换内容；上一请求的迟到回调不能覆盖新内容。 |
| 关闭后重新触发，或退出应用后重新启动 | 创建新的未固定浮窗。可以记忆尺寸和合理的位置偏好，不恢复上次固定状态。 |

“固定”是临时浮窗是否常驻的唯一用户可见控制。旧 `hide_on_focus_loss` 字段不能继续成为导致未固定浮窗常驻的隐藏开关；自行设计兼容迁移，保留无关用户偏好及几何数据。

不要把每一次 Qt 失焦都直接等同于离开窗口。快捷键触发、菜单收起、子菜单、拖动缩放和原生窗口更新都需要正确归属。窗口策略应有集中、可测试的状态来源，避免多处布尔值、按钮文字和计时器分别决定同一行为。

关闭时先释放当前 UI 会话，再取消底层工作。即使 Ollama 仍在完成模型加载，新请求也必须能立即显示自己的原文和窗口；旧请求不能重新弹出窗口或清除新会话。

### 3.2 固定按钮

- 使用图钉矢量图标：未固定为轮廓，已固定为实心并有适度背景强调；不能只靠颜色区分。
- 按钮位置和尺寸固定，不通过 `Pin` / `Pinned` 文字长度变化表达状态。
- 悬停和辅助功能名称明确说明当前状态与动作，例如“固定窗口，点击外部仍保持显示”/“已固定，点击取消固定”。
- 图标、选中状态、提示、原生层级和外部点击策略从同一状态同步；首次显示与恢复场景也适用。
- 切换不能产生可见闪烁、位置跳动、滚动复位或选区丢失。优先维持同一个原生窗口，选择合适的层级更新方式，不依赖隐藏后重显来切换固定。

### 3.3 About 与其他菜单窗口

About 单击应在前台出现并可交互；再次点击复用已有窗口，关闭后再次单击也应正常。已有固定翻译窗不能挡住 About。Settings 等入口遵循一致的展示策略。

执行时先观察菜单关闭、应用激活、窗口创建与前置的事件顺序。可以共用窗口协调机制；不要求照搬现有 Settings 的延迟回调实现。避免用不断增加延迟或反复调用显示操作掩盖时序问题。

## 4. UI 方向

阅读浮窗的概念结构如下；执行 agent 可自主完善视觉设计。

```text
英语 → 简体中文                             [图钉] [更多]

原文摘要，默认两三行……                       [朗读]
展开原文

译文正文
……
                                            [复制] [朗读]
```

- **阅读优先。** 译文获得主要空间；原文默认只读，长原文可展开。短词保持紧凑，长文合理增高后滚动。用户手动调整尺寸后，不随流式输出持续改动窗口大小。
- **操作按需出现。** 等待/生成时提供停止；失败或停止后提供适当的重试/继续入口；用户离开滚动底部时才出现“回到末尾”。完成状态不保留一排禁用按钮或常驻字符统计。
- **常用操作直接完成。** 点击复制默认复制译文，原文和双语复制进入次级菜单。原文、译文各自的朗读靠近文本；有选区时读选区，无选区时读全文，播放中可停止。
- **简化外观。** 保留可靠的原生拖拽、边缘缩放和关闭能力，去掉内容区重复的关闭按钮；减少粗边框、大输入框外观和重复分隔。浅色、深色和系统主题均需清楚可读。
- **语言信息简洁真实。** 使用易读的短名称。显示“自动”或实际识别语言，不为了布局伪造已识别结果。UI 文案风格保持一致。
- **低频操作收拢。** 编辑原文、双语并排、其他复制方式、音色等放在合适的二级入口；不能因为精简主界面而删掉既有能力。

原文编辑、OCR 校对和手动输入使用明确的编辑界面或模式，采用普通窗口的保留规则，避免丢失尚未提交的输入。阅读浮窗不因原文框偶然可编辑而悄悄进入“不会消失”的状态。编辑完成、取消及返回阅读的路径需清楚；具体采用独立窗口还是共享视图由执行 agent 决定。

菜单栏保留翻译、OCR、输入翻译、设置、About、退出等清晰入口。权限与故障诊断按需要呈现。设置界面区分常用偏好与高级参数，连接地址、上下文、超时等不占据普通阅读操作的主要空间。

## 5. 必须保留的现有能力

- MiLMMT 官方 raw 提示、解码配置、本地语言识别和每段最多 2048 UTF-8 字节的策略。具体见 [模型适配记录](MILMMT_DEFAULT_2026-09-26.md)。本次不重写既有模型评测结果。
- 流式输出不替换/扩大选区；向上阅读时不强制滚回末尾；复制内容与显示内容一致。
- 完整源文本、不静默截断、仅完整分段进入续译检查点；源文、语言或模型变化后失效旧检查点。
- 冷启动可取消，旧任务与新会话隔离；不遗留网络工作、线程、鼠标监听或语音播放。
- OCR 校对、取消截图、用户剪贴板保护，以及系统离线朗读。
- 用户配置、可用的签名身份和包标识；内容日志与翻译历史不因本轮改造被默认开启。

每完成一个有意义的阶段就 commit，一并提交对应回归与说明。可以按实际依赖调整拆分，不要求机械照搬四个提交；不要把已授权范围内的普通实现选择变成反复确认流程。

## 7. 验收要求

现有 UI 测试部分屏蔽原生外部点击监听，直接发出模拟信号；它们可以验证状态处理，不能证明真实外部点击能够送达，也不能证明没有闪烁。应补充行为回归，并用正常启动的签名 `.app` 完成下面的交互验证。

| 验收组 | 需要证明的结果 |
| --- | --- |
| 菜单窗口 | 应用在后台、前台及存在固定窗时，About 首次单击均可见可操作；重复开启/关闭不出现重复窗口。Settings 同样稳定。 |
| 固定状态 | 加载旧 `pinned=true` 状态后，新窗口仍未固定；连续切换至少 20 次无可见闪烁、跳位或选区丢失；关闭再开及应用重启后状态一致。不能只断言按钮 `isChecked()`。 |
| 外部交互 | 在浏览器、PDF 阅读器或文本编辑器中触发；等待模型、流式、完成、停止/错误各状态下，未固定窗外部点击收起，固定窗保留。窗口自己的菜单、拖动、缩放、复制和朗读不导致误关闭。 |
| 会话与取消 | 模型未驻留时触发，首字前关闭，立即再次翻译；新窗口正常出现，旧输出不回流。重复打开/关闭后监听与工作任务得到释放。 |
| 阅读与编辑 | 流式选词、反向选区、滚动、复制、朗读正常；长原文可访问；编辑和 OCR 校对不被意外丢弃，提交/取消路径明确。 |
| 布局与安装 | 短词、长段落、中日英文本、浅深主题及小窗口下无明显拥挤或截断；验证实际安装版本、模型和用户偏好。已有屏幕条件下检查位置恢复、最小化与 Space 行为。 |

能自动化的边界应自动化；闪烁、前台显示、真实鼠标事件和阅读布局须有真实交互证据。截图可证明布局，不能单独证明无闪烁。没有条件验证的多屏等场景明确标记，不以模拟通过替代实测，也不把不可用硬件当作无限拖延交付的理由。

验收记录应简短地给出：实现版本/commit、测试命令及结果、正常应用启动的交互结果、必要截图或事件证据、未验证事项和回退位置。源码测试与安装包验证要分开描述。
