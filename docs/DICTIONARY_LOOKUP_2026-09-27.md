# 单词查词卡片 · 原型与实现记录

## 问题

选中单个单词时，只输出一句模型翻译信息太少。系统词典的公开查询接口在所有已启用的词典中取第一个匹配，
本机实测会出现以下情况：`ran` 返回汉英部分的“蚺 rán”，`mice` 返回 Apple 词典的 Magic Mouse，
`inhibited` 只返回“拘谨的”，生物医学术语则只有英文释义。

## 做法

参考 Easydict、Bob，通过 DictionaryServices 的记录接口按标识符查询指定词典，读取词条 XHTML：

- 英汉 / 汉英：`com.apple.dictionary.zh_CN-en.OCD`（牛津英汉汉英词典）
- 英英兜底：`com.apple.dictionary.NOAD`（New Oxford American Dictionary）

变形由词典自己的索引处理（inhibited→inhibit，ran→run 并注明“过去式”，mice→mouse）。
英文查询只保留不含汉字的词头，因此不会再返回按拼音匹配到的“蚺 rán”。这些接口不在公开 SDK 中，采用防御性加载：
加载失败时查词不返回结果，自动改用模型翻译。

## 原型测量

测试集共 88 个词，来自读论文的场景：变形 20、学术常用 20、生物医学 30、多义 15、中文 3。
脚本为 `scripts/evaluate_dictionary.py`，结果见 [JSON](research/dictionary_prototype_2026-09-27.json)。

- 74 个词查到英汉词条，13 个改用英英释义，1 个两本词典都查不到（ubiquitination，改用模型翻译）。
- 耗时中位数 1.5 ms，最长 29 ms（首次读取 run 这类大词条）；安装包内自检也在同一量级。
- 变形全部正确还原，包括不规则形式 ran、mice、criteria、phenomena、hypotheses。
- 很多学科义项带领域标签，例如 cell ②［Biology］细胞、host ④ 寄主、medium ⑤ 培养基。
  但也有论文义项缺失：promoter（启动子）、pathway（通路）、transcription（转录）、resolution（分辨率）、knockdown（敲低）。
- 不给上下文时，模型对多义词同样倾向日常义：promoter→发起人、knockdown→击倒、resolution→决议、host→主持人。
  但对词典未收录的专业术语，模型译名准确：泛素化、激酶、细胞凋亡、配体、抗原表位、转录。
  模型加载后每个词约 0.2 秒。

## 设计（参考 Bob、欧路、macOS 查询、Easydict）

- 词头，以及变形说明（“ran 是 run 的过去式”或 “inhibited → inhibit”）。
- 英 / 美音标，点击后用系统语音离线朗读。
- 词性、编号义项和领域标签：学科领域的义项高亮并加粗，每个词性只显示一条例句。
  长词条默认收起，显示“另有 N 个义项”，点击展开。
- 词典有英汉词条时，结果即时显示；模型译法在后台补上，并标注“无上下文，仅供参考”。
  词典没有英汉词条时，先显示词头和音标，再用较大字号显示模型译名，然后是英英释义。
- 最后一行注明词典来源。“⋯”菜单中可以选择“用模型翻译”；设置 → 通用 → 翻译中可以关闭查词。
- 词组和其他语言对仍然使用模型翻译。

## 用户试用后的补充（0.4.0）

用户反馈 Equivariance、Inpainting 只出现了翻译、没有词典。核查结果：两本系统词典都未收录这两个词，小写形式和词根
（equivariant、inpaint）也都没有，与大小写无关，退回模型翻译属于预期行为。问题在于界面上看不出词典已经查过。
现在单个词两本词典都查不到时，同样显示卡片，注明“系统词典未收录此词，以下为模型翻译”，并以较大字号显示模型译名。

模型对这类较新的机器学习术语并不可靠：Equivariance 译成“等价性”（正确应为“等变性”），Inpainting 译成“重绘”
（常用译法是“图像修复 / 补全”）。卡片明确标注这是模型译名，不会被当作词典结果。

## 已知限制

- 系统词典不收录较新的专业术语（尤其是机器学习领域），模型对这类术语也可能译错；
  可以考虑由用户维护的术语表来补充。
- 多义词的论文义项要靠用户在列出的义项中辨认，自动取舍需要句子上下文，这一项尚未实现。
- 依赖私有接口，macOS 升级后可能失效，失效时自动退回模型翻译。
- 用户需要在“词典”App 中启用牛津英汉汉英词典；未启用时会自动退回模型翻译。
