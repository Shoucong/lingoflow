# LingoFlow 0.2.0 本机验收

本轮完成 Python/PyQt6 路线的窗口、朗读、任务、macOS 采集、长文、设置、架构与打包改造。
默认仍使用原有 7B 模型。当前证据没有触发全量 Swift 迁移；术语表、历史和原生重写仍是
规划中的可选/条件项。真实外部应用划词、安装后权限和多屏等人工项目单独列在末尾。

## 自动与原生验证

- 在锁定依赖的独立 Python 3.12.12 环境中：**137 项回归通过，54 项 Cocoa 界面测试通过**；
  Ruff、Git diff 检查通过。Cocoa 是上述界面用例换原生后端运行，不是另加 54 项独立用例。
- PyQt6 6.11.0、Qt runtime 6.11.1、PyObjC 12.1、PyInstaller 6.20.0；50 个依赖包含版本和
  wheel 哈希，下载后离线安装。首次干净安装发现缺少 editable 构建依赖，已将 `editables`
  纳入锁文件后重装通过。QtCore 的最低部署目标为 macOS 13.0。
- 包内自检运行真实 `.app`：30 次创建、关闭、最小化、恢复、流式选区保留、隐藏后继续接收；
  每次注册两个 AppKit 鼠标监听，关闭后均为零。合成图片的 Vision OCR 识别保留 `12.5` 和 `[12]`，
  自有临时增强图片清理后为零。自检的窗口截图已逐张检查。
- 首次源码进程 Vision 调用约 62.9 秒，进程采样显示系统识别模型初始化/编译；随后首次包内
  调用约 0.35 秒。日用流程在后台执行 OCR，这个冷启动成本仍可能出现。
- 真实 Ollama 在首字前和流中取消：客户端分别约 **28 ms / 3 ms** 退出，活动请求归零；
  之后的新翻译成功。这证明客户端传输回收，不等同于测量服务器内部 GPU 调度停止时刻。
- 连续创建并回收 250 个任务后：活动任务 0，仅保留 100 条有界诊断，Python 线程从 1 回到 1。
  30 次窗口循环是有限时长检查，不能替代数小时常驻或睡眠唤醒测试。

## 本地模型对照

环境：Apple M1 Pro、16 GB、macOS 27.2、Ollama 0.34.3。使用 30 段自己编写的合成文本；
三种配置共 90 次翻译。未下载模型，未读取个人论文/剪贴板，未调用云端推理。
新配置为 context 8192、output 2048、temperature 0.1、keep-alive 300 秒，能力支持时关闭 thinking。

| 配置 | T02–T29 首字中位数 | T02–T29 总时长中位数 | 6525 字符长文 |
| --- | --- | --- | --- |
| 7B 原参数及旧选区限制 | 0.185 秒 | 0.997 秒 | 只传入 5000 字符；47.9 秒；缺失末段 |
| 7B 新配置 | 0.184 秒 | 0.996 秒 | 完整传入，2/2 段；60.7 秒；保留尾部标记 |
| 已安装的 Gemma3 translator 4B | 0.410 秒 | 0.868 秒 | 完整传入，2/2 段；37.9 秒；保留尾部标记 |

旧配置调用使用新严格解析器，并非旧 `.app` 二进制性能测量。剔除首个请求及长文后的短文本
中位数只作描述；执行期间存在其他验证工作，没有控制缓存、温度和系统负载。各配置首次
请求的模型驻留状态、模型 digest、准确 tag、量化、原始译文和耗时均在 JSON 中。
新 7B 与 4B 的长文都覆盖 28 个编号数值且无重复；旧选区对照缺少尾部数值及 `END-928`。

三组都收到正常完成帧，但这不能证明语义翻译完全正确。逐项阅读短文本后可见：

- 两个模型都会把缺乏上下文的 “window” 译成“窗户”；7B 还把一处 “paper” 译成“试卷”。
- 4B 的某些 OCR 断行和中文句式较生硬；长文后半段部分标题保留英文，且 T29 去掉了 LaTeX
  的反斜杠定界符。分段器保护原文中的公式，不保证模型输出逐字保留公式格式。
- 字面检查对日期本地化和全角括号有误报，不能把这类计数当准确率。

因此保持 7B 默认，4B 可在 Settings 中选择后按实际材料比较。学术 preset 和自定义提示词
已可用，但没有足够质量证据宣布某个模型全面胜出。

## 构建与人工边界

最终应用位于 `dist/refactor-20260926/LingoFlow.app`，版本 0.2.0，arm64。
同目录的 `LingoFlow.dmg` 约 44 MiB，已通过 `hdiutil verify`，只读挂载后再次检查包内
签名、Applications 链接和可执行文件 SHA-256；与直接构建的应用一致。
构建使用 Keychain 中**已有的** `LingoFlow Local Development` 身份，严格深度签名验证通过；
本轮没有创建/信任新证书，也没有替换 `/Applications/LingoFlow.app`。

包内只读权限检查：Accessibility 和 Input Monitoring 为 **missing**，Screen Recording 为
granted。因此没有把浏览器/PDF/编辑器中的真实全局快捷键和选区采集标为已验收。
这里测的是直接运行测试包时的权限状态，并非对替换安装后 Finder 启动身份的验证。
安装后若权限缺失，需用户在 macOS 系统设置中完成；签名通过不代表 TCC 权限会跨安装自动保留。

其余未做的人工项目：英美/中文实际扬声器试听与断网播放、物理多屏及全屏空间、睡眠唤醒、
数小时常驻、重装后的权限保持，以及安装 Easydict 后的同模型交互对照。对标应用本轮采用
已记录的公开源码分析。详细步骤见 `manual_tests/README.md`。

当前无需为了这些已修复的窗口问题立即更换 Python。若授权后的日常验收仍反复出现 Qt/AppKit
焦点或窗口层级问题，再启动规划中的 Swift 小原型，并沿用本次固定评测集。

证据：`research/model_evaluation_2026-09-26.json`、`research/runtime_validation_2026-09-26.json`、
`research/bundle_validation_2026-09-26.json`、`research/speech_validation_2026-09-26.json`。
