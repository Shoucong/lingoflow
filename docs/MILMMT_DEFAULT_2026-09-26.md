# MiLMMT 默认模型 · LingoFlow 0.2.1

本机默认翻译模型调整为 `hf.co/mradermacher/MiLMMT-46-4B-v1.0-GGUF:Q4_K_M`。
它是本次对照过的社区 GGUF 量化，提示格式和解码方式依据
[小米官方说明](https://github.com/xiaomi-research/gemmax#-translation-prompt)。

**生效方式。** 使用 `/api/generate` 的 raw completion，明确传入源语言和目标语言；
中文语言名称映射为官方要求的 `Chinese (Simplified)` / `Chinese (Traditional)`。
温度 0、top_k=1、repeat_penalty=1，关闭思考；默认上下文 8192、每段输出预算 2048、驻留 300 秒。
后面三项为应用设置，并非官方规定的统一最优值。系统提示、自定义提示、学术风格和聊天上下文前缀
不混入这个专用模板。设置界面禁用不适用的控件，但保留自定义提示供其他模型使用。

**自动识别。** 用 macOS 自带语言识别在本机确定源语言，然后构造明确语言的官方提示。
对于 `kinase` 这类缺少上下文的孤立拉丁词，默认按英语处理；需要其他语言时可手动选择 Text Source。
简繁中文分别识别，原文已是目标语言时原样返回。源语言不能确认时提示手动选择，不发送 `from auto`。

**长文。** 保留完整原文，分段单独翻译，仍支持取消和已完成分段的续译。
实机压力测试发现：把 E25 人为重复三次，在较大的输入分段中，模型自行合并重复内容并漏掉第二个标记，
即使 API 返回正常结束也会如此。原始失败的
[诊断记录](research/milmmt_repeated_long_text_diagnostic_2026-09-26.json) 已保留。
将 MiLMMT 每段源文本限制为最多 2048 UTF-8 字节后，同一案例保留了三个标记，日语重复长文也保留全部标记。
这是应用分段策略，不是模型官方上下文上限；标记齐全也不能证明逐句语义完全正确。
