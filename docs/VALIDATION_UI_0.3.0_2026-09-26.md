## 实现要点

- **固定只属于当前窗口。** 不再读写 `pinned`；旧文件中的 `pinned=true` 读取时丢弃。只记忆用户手动调整的尺寸。
- **固定不闪烁。** 旧实现 `QWidget.setWindowFlag` + `show()` 会重建原生窗口并隐藏再显示。现在改为修改现有 QWindow 的层级
  （NSWindow level 0↔8），窗口、几何、焦点、滚动和选区都不变。图钉图标、选中状态、提示、辅助功能名称和原生层级由同一个值同步。
- **收起规则只在一处判断**（`TranslationPopup._auto_dismiss_allowed`）。未固定的阅读窗口在以下情况收起，
  等待模型、流式、完成、停止、出错各状态都一样：点击其他应用或桌面（AppKit 全局鼠标监听），
  或切换到另一个普通应用（NSWorkspace 激活通知）。以下情况不算离开：
  - LingoFlow 自己的窗口、菜单、状态栏图标；
  - 后台 UI 代理进程；
  - 回到窗口出现时正在阅读的那个应用。

  只用于关闭已打开菜单的点击同样不会收起窗口。隐藏的 `hide_on_focus_loss` 设置已移除，旧配置仍可正常读取。
- **编辑是明确的模式。** 手动输入、OCR 校对和“编辑原文”带“翻译 / 取消”按钮，按普通窗口保留；未提交的修改在 Esc、取消或关闭按钮时先确认。
- **菜单窗口统一展示。** 菜单命令在菜单关闭后的下一轮事件循环执行，然后依次激活应用、显示、前置、获得焦点，已打开的窗口直接复用。
  菜单窗口处于活动状态时浮在固定窗之上。About 改为可复用的非模态窗口；打开设置不再关闭阅读窗口。
- **阅读界面。**
  - 标题行显示语言短名称；源语言在本机识别后显示实际语言，否则显示“自动”。右侧是图钉和“⋯”。
  - 原文默认显示三行摘要，可展开。按钮只在对应状态出现：停止、重试 / 继续翻译、回到末尾。
  - 复制按钮复制当前显示的译文；复制原文、复制双语、并排显示、朗读设置都在“⋯”菜单里。
  - 全部界面改为中文。
- **设置分组：** 通用 / 朗读 / 模型与高级（英文界面为 General / Speech / Model & Advanced），原有选项全部保留。
- **界面语言（安装后用户要求）。** 默认 English，可选中文，适用于阅读窗口、菜单栏、About、设置、权限窗口、
  通知和翻译错误提示。每条文字在调用处用 `lingoflow.i18n.tr(英文, 中文)` 同时写出。保存后立即生效：
  菜单栏和已打开的阅读窗口原地刷新文字，固定状态、内容和译文语言不变。旧配置文件没有该字段，按 English 读取。

新增或改写的回归覆盖：

- 旧状态文件 `pinned=true` 不会固定新窗口，关闭再开后也不会；
- 固定连续切换 20 次：没有 Hide / WinIdChange 事件，原生窗口不变，几何、滚动和选区不变；
- 未固定窗口在五种状态下外部点击都收起；固定窗保持，取消固定的那次点击不收起；
- 应用切换的判定表；只关闭菜单的点击；最小化窗口不收起；
- 编辑模式的提交、取消、确认，翻译中禁止编辑；
- 按状态出现的操作、复制内容、原文摘要展开、回到末尾；
- 开始高度与只增不减；
- About 复用与置前、菜单命令在菜单关闭后只执行一次、设置窗口复用与分区；
- 针对真实 AppKit 的监听注册与释放。

**测试漏掉、原生检查发现的问题：** 应用切换监听最初用错了 PyObjC selector（`..._handler_`），导致监听整体安装失败。
单测的假对象沿用了同一错误名称，所以没能发现。包内自检检查到每个窗口的监听数为 0，因此已修复并加入真实 AppKit 回归。

## 安装时发现的问题

加入界面语言后第一次安装的包启动即退出。原因是给 `&` 加注释时，行尾注释把同一行的中文参数注释掉了，
`TrayController` 抛出 TypeError。日志停在 HotkeyManager 初始化之后，没有进入事件循环；直接运行二进制可以看到
traceback。测试没有发现，是因为测试从不构建可选的“权限与诊断”和“输入文字翻译”菜单项；包内自检也不创建菜单栏。
已修复，并加入在两种语言下构建完整菜单的回归。重新安装后，日志确认进入事件循环、快捷键监听已启动。
此后每次安装都检查日志中的 `Application started, entering event loop`，不再只看进程是否存在。
